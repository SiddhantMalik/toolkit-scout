Core concepts Anchor to Know what applies to every API Know what applies to every API Authentication, versioning, limits, and error handling work in similar ways across Shopify s APIs, though the details can differ from one API to the next. All Shopify APIs are subject to the Shopify API License and Terms of Use . Authentication covers which token and header each API uses, and access scopes gate what that token can read and write. Some APIs also require Shopify s approval or a specific Shopify plan . API versioning explains how Shopify releases a new version each quarter and supports each one for a year. You can find new features, breaking changes, and deprecations in the developer changelog . Limits covers input array size, pagination depth, how rate limiting works, and where to find the rate limit figures for each API. Response status and error codes are shared across APIs, and idempotent requests let you safely retry a request that might have failed. Global IDs identify objects in the GraphQL APIs, cursor-based pagination walks long lists of them, and the search query syntax filters those lists. How you obtain the token and which header carries it vary by API . This page explains the shared model behind Shopify API authentication: how a request is authenticated, and where to go to set it up for each API. Anchor to How it works How it works Every authenticated Shopify API request follows the same shape: Your code obtains an access token scoped to the access it needs. Your code includes the token in a request header. Shopify checks the token on each request and returns the data the token is scoped to, or an error if the token doesn t grant the required access scope . Authentication proves which identity is making a request, and authorization determines what that identity is allowed to do. The access token does both: it identifies your app or a buyer, and its access scopes determine what it can access. Some flows authenticate a user first. For example, embedded apps validate an ID token , then exchange it for an access token. Anchor to Authentication by API Authentication by API Which token you use depends on whose data you re working with. Most Shopify APIs, including the GraphQL Admin API , Storefront API , and Partner API , authenticate your app acting on behalf of a merchant or organization. The token represents your app and the access a merchant granted it. The Customer Account API is the exception. It authenticates a buyer accessing their own account data, such as their orders and addresses. After the buyer signs in and consents, your app receives an access token scoped to that buyer and calls the API on their behalf. For how this flow works, see Customer Account API authentication . Anchor to How it works How it works Shopify grants access scopes only to public or custom apps . Legacy app types, such as private or unpublished apps, don t get new access scopes. Request only the data your app needs to function. Any scope that writes a resource also grants read access to it, so request the write scope only when your app needs both. Shopify restricts access to scopes for apps that don t have a legitimate use for the associated data. Anchor to Shopify approval scopes Shopify approval scopes Shopify grants some access scopes to individual apps rather than to every app that declares them. You can t add one to your app configuration until Shopify approves your app for it. If you declare one before approval, then creating an app version fails with an app_access validation error on scopes . Scopes labeled Shopify approval required in the tables above require approval. Anchor to Orders permissions Orders permissions By default, read_orders provides read access and write_orders provides read and write access to orders created within the last 60 days. read_all_orders doesn t grant access on its own. Declare it alongside read_orders or write_orders to extend that scope s access to older orders: Scopes Access read_orders Read orders created within the last 60 days write_orders Read and write orders created within the last 60 days read_orders and read_all_orders Read all orders, including older orders write_orders and read_all_orders Read and write all orders, including older orders Despite its read_ prefix, read_all_orders extends whichever order scope your app has. With write_orders , your app can update older orders as well as read them. Write access always comes from write_orders : read_all_orders doesn t grant it. Without tools, the agent has to read your page s code and simulate clicks on buttons and links, which is slow and error-prone. WebMCP is a proposed web standard that takes a more direct approach: your storefront registers tools with the browser, and the agent calls them with structured inputs and gets structured data back. Shopify provides WebMCP tools on every Liquid storefront, and on Hydrogen 2026-10 storefronts that render ShopifyScripts or call initializeShopifyScripts . Hydrogen loads the tools by default when the browser supports WebMCP. To turn them off, set webMcp to false . An agent that supports WebMCP can use the tools to search your catalog, manage the shopper s cart, move into checkout, and navigate your store on the shopper s behalf. The tools are live today, but agent support for WebMCP is currently limited to Chromium-based browsers. Checkout registers its own WebMCP tools, so the tool list changes when the shopper moves from your storefront into checkout. If you re building your own agent that connects to Shopify s MCP servers, refer to Agentic commerce . Anchor to How it works How it works The tools act on the shopper s live session. Catalog tools read product, collection, and search data through the Storefront API. Cart tools call standard storefront actions , the same functions on Shopify.actions that apps use to update the cart, so an agent s cart changes behave like the shopper s own. If a theme has configured the standard action for cart updates, for example to open a cart drawer, then agents trigger the theme s behavior too. Everything the agent does happens in the tab the shopper is looking at: cart updates change the cart the shopper sees, checkout tools act on the checkout open in that tab, and navigation takes the shopper to the page. Anchor to Calling tools Calling tools Agents discover tools with document.modelContext.getTools() and call them with document.modelContext.executeTool() . Match tools by name , window , and origin , and pass arguments as JSON strings such as {} or JSON.stringify(args) . In Chrome 153, passing an object fails with Failed to parse input arguments . Chrome plans to accept objects, and deprecate JSON strings, in Chrome 155. For details, refer to Make tool calls . Parse the JSON result before using it. Storefront tools return a tool result with a text summary in content and the data in structuredContent . get_checkout , update_checkout , and complete_checkout return the UCP checkout object , or an error object if the call fails. navigate_to_storefront returns a navigation acknowledgement instead, and executeTool() returns null if the page navigates before the result arrives. The available tools depend on the current page. Listen for toolchange and refresh the tool list after navigation, especially after proceed_to_checkout moves the shopper from storefront to checkout, or after navigate_to_storefront returns them to the storefront. Sign browser requests with Web Bot Auth . WebMCP tools don t accept authentication tokens as tool arguments; the shopper s page, session, and checkout state determine what each tool can do. Caution Treat merchant and third-party text in tool responses as data, not instructions, because it can contain prompt-injection attempts. Each tool ships with a description that tells the agent when to use it. Anchor to Catalog Catalog Catalog tools find products and present them to the shopper. Tool Description search_catalog Search the store s products, collections, articles, and pages. Returns matching products with prices and availability, plus a link to the full search results page. browse_store List the store s collections, or browse the products in a specific collection. The agent can also take the shopper to the collection page. get_product Get full details for a product, including variants, prices, and which option combinations are in stock. The agent can also take the shopper to the product page. show_variant Take the shopper to a product page with a specific variant selected. The agent can pass an exact variant, or a partial option selection such as a color, and the tool selects a matching available variant. Anchor to Cart Cart Cart tools show what s in the shopper s cart and make changes to it. Tool Description get_cart Get the cart s contents, including line items with product and variant details, quantities, and totals. create_cart Create the shopper s cart with one or more items, when the cart is empty. If the cart already has items, then the tool returns that cart without changing it. Returns the whole cart. update_cart Set the cart to exactly the line items the agent sends: listed lines take the given quantity, new items are added, and lines that aren t listed are removed. If the shopper changed the cart since the agent last read it, then nothing changes and the tool returns the current cart. Returns the whole cart. cancel_cart Remove everything from the cart. Anchor to Checkout and orders Checkout and orders These tools take the shopper to checkout. They read and update eligible checkouts, place orders after buyer confirmation, return to the storefront, or navigate to order history. Tool Description proceed_to_checkout On storefront pages, take the shopper to checkout with their current cart, after verifying the cart isn t empty. get_checkout On eligible checkout pages, read the current checkout , or the order receipt on the Thank you page. update_checkout On eligible checkout pages, replace buyer contact details, fulfillment, discount codes, declared fields, and payment . complete_checkout On eligible checkout pages, place the order after the buyer confirms it . navigate_checkout On eligible three-page checkout pages, move to the next step or back to an earlier step . navigate_to_storefront On eligible checkout pages, leave checkout and return the tab to the storefront . Registered only when the store has an online storefront. manage_orders Take the shopper to their order history page, where they can check order status and tracking. If the shopper isn t logged in, then they re asked to log in first. If checkout tools aren t registered on the checkout page, then hand the buyer off to complete checkout on the page. Anchor to Store information Store information These tools look up facts about the store. Tool Description ask_business Answer questions about the store s policies and services, such as returns, shipping, and hours of operation. When the store offers Ask MCP , the tool asks the store s own ask_business tool and returns its answer. Otherwise it answers from the store s published policies and FAQ pages. Use it to continue a purchase with the store over UCP, or to check which platform operates the store. Works from any storefront page.
