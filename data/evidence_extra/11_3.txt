--- title: Understanding the differences between API tokens and OAuth access tokens url: https://developer.zendesk.com/documentation/authentication/oauth-vs-api-tokens/ markdown_url: https://developer.zendesk.com/documentation/authentication/oauth-vs-api-tokens.md collection: documentation breadcrumbs: - Authentication --- # Understanding the differences between API tokens and OAuth access tokens Both API tokens and OAuth access tokens let you authenticate Zendesk API requests without providing your Zendesk password. However, the token types support different creation methods and permission setups. For server-to-server communications where a broad permission set is appropriate, API tokens might be sufficient and easier to manage. For applications needing to act on behalf of specific users, OAuth tokens provide a more secure and targeted approach. The following table describes some key differences between API tokens and OAuth access tokens. | Difference | API tokens | OAuth access tokens | | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | | Creation and management | Created and managed using Admin Center. See [Generating a new API token](https://support.zendesk.com/hc/en-us/articles/4408889192858) in Zendesk help. | Created and managed using Zendesk API requests.<br><br>However, you can create OAuth clients using Admin Center. See [Registering your application with Zendesk](https://support.zendesk.com/hc/en-us/articles/4408845965210#topic_s21_lfs_qk) in Zendesk help. | | User association | Not associated with a specific Zendesk user.<br><br>However, you must provide an email address for an admin, agent, or other valid user when authenticating requests. | Associated with a specific Zendesk user. | | Permissions | Permissions are limited by the user role associated with the provided email address. This means the scope of what the token can access or change is limited by what the associated user is permitted to do within Zendesk. | Permissions are limited by [scopes](https://developer.zendesk.com/api-reference/ticketing/oauth/grant_type_tokens/#scope), the associated user's role, and any allowed scopes configured on the OAuth client by an admin. Allowed scopes define the maximum set of scopes a client can request, enabling admins to apply the principle of least privilege to applications that integrate with Zendesk. | | Cross-origin resource sharing (CORS) requests | Doesn't support client-side CORS requests. | Supports client-side CORS requests. See [Making cross-origin, browser-side API requests](https://developer.zendesk.com/documentation/ticketing/using-the-zendesk-api/making-cross-origin-browser-side-api-requests/). | For more information, see [Security and authentication](https://developer.zendesk.com/api-reference/introduction/security-and-auth/).
