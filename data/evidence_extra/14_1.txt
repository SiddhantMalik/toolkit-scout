--- updatedAt: 2026-11-12T15:54:00.000Z agentTools: projectIndex: https://dev.frontapp.com/llms.txt --- # MCP Server ## Connect AI assistants to Front via the MCP server Front's MCP server (`mcp.frontapp.com/mcp`) lets AI agents act on Front conversation data using a single OAuth-authenticated endpoint. Agents authenticate as a specific Front user, with permissions matching that user's role (user-scoped authorization). The MCP server is separate from the [Admin MCP server](https://dev.frontapp.com/docs/admin-mcp-server), which manages Front configurations such as rules, setting up teammates, managing AI features, etc. &#x20;This article covers how to connect the MCP server to any MCP-compatible client to Front using an OAuth app you create yourself in the Front developer settings. For the user-facing overview, official directory listings (Claude, and others coming), and use case inspirations for Front teammates, see the general [Help Center article on the MCP server](https://help.front.com/en/articles/4883136). > **Looking for examples before you build?** > > The [MCP space in the Front Community](https://community.front.com/mcp-server-88) has workflow walkthroughs, sample prompts, and more. You can also start up discussions about the MCP server with fellow users and our team. ## Overview | | | | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | | **Endpoint** | `https://mcp.frontapp.com/mcp` | | **Transport** | Streamable HTTP | | **MCP spec version** | 2025-11-25 | | **Auth** | OAuth 2.1 + PKCE compatibility<br /><br />**Note:** Front does not support Dynamic Client Registration. Your AI assistant must support a ***confidential connection that sends an OAuth client ID and secret***. Some popular AI assistants are currently [not compatible](#incompatibility-list). | | **Identity model** | Per-user tokens. Every tool call attributes to a specific Front teammate | | **Who can connect** | Any teammate | | **Scopes** | `read`, `write`, `send` | The identity model is the part most worth internalizing: the agent's effective permissions are exactly the authorizing teammate's permissions. If the teammate can't see an inbox, the agent can't either. ### Incompatibility list Some AI assistants do not support confidential connections. These clients cannot connect to the Front MCP server: * Any client that requires Dynamic Client Registration (DCR) ## Use cases A few patterns this surface unlocks: * **Custom agent harnesses.** Wire Front into Claude Code, Cursor, or an in-house orchestrator alongside your other tools (GitHub, Notion, Jira, Slack, Linear, your CRM) for cross-system workflows: customer reports a bug, agent reproduces it, identifies the suspect PR, and posts an internal comment with the diagnosis. * **Multi-tenant partner integrations.** Publish an OAuth app that any Front admin can install. Each end user authorizes individually. * **Triage and routing agents.** Scheduled or event-driven agents that search the inbox, classify by topic, assign to the right teammate, and draft a first-pass reply for human review. * **Conversation insights and enrichment.** Pull conversation data into your own pipelines for analysis, KB extraction, or feedback ingestion. The conversation timeline includes messages, comments, tags, assignment history, and more in a single stream. ## Set up the MCP server connection <Callout icon="📘" theme="info"> ### Connect Claude and ChatGPT/Codex from the official directory If you're using Claude or ChatGPT, we recommend you connect the Front MCP server from the official directories:<br /> * &#x20;[Claude official directory](https://claude.ai/directory/connectors/front)&#x20; * [ChatGPT official directory](https://chatgpt.com/plugins/plugin_asdk_app_6aaab462482c819183764e2f6a72e8e9) <br />If you install Claude or ChatGPT from the official directories, you do not need to complete either step in this section (**Set up the Front developer app with the Front MCP feature** or **Connect your AI assistant)**. If you are not using Claude or ChatGPT, follow the steps in this section to set up the MCP server as a custom connector. To connect via an official directory: - A Front admin (or any user authorized to install integrations from the Front App Store) must connect via the directory links above. - Then, any user in your company can use the directory links to connect their own accounts. </Callout> Connecting an AI assistant to Front's MCP server has two general steps: create a Front developer app with the Front MCP feature, and then connect your AI client using the app's credentials. <Callout icon="👍" theme="okay"> After you complete these two steps, your teammates will be able to find the Front MCP server in your AI assistant and connect to it without having to create a developer app or configure the connection details on the AI client side. </Callout> ### 1. Set up the Front developer app with the Front MCP feature <Callout icon="👍" theme="success"> ### These instructions are completed in your Front settings (Settings > Company > Developer) </Callout> <Callout icon="👍" theme="success"> ### If you want to authorize the MCP server on behalf of an AI agent, skip setting up a Front developer app and instead use the [OAuth credentials associated with the AI agent](https://dev.frontapp.com/docs/ai-agents#ai-engine). </Callout> 1. [Create a developer app](https://dev.frontapp.com/docs/create-and-manage-apps) and give it an appropriate name (e.g. "Claude MCP Connector"). 2. Click **Add feature** in the **Features** tab and select **Front MCP**. 3. Note the **Client ID** and **Client secret**. 4. Add a **redirect URL** that corresponds to the AI assistant you're sending data to. For example, as of this writing, the Claude documentation instructs you to use `https://claude.ai/api/mcp/auth_callback` for most versions of Claude. If you're using Claude Code or similar CLI, you should enter `http://localhost/callback`. This URL will allow you to connect to a randomly generated local port. 5. Under **Resource permissions**, select the resources available to the MCP server. <Callout icon="👍" theme="okay"> Request the narrowest set that covers your use case. A read-only research agent only needs `read`. A drafting copilot needs `read` + `write` but not `send`. Only request `send` if your agent will actually send messages. </Callout> <Callout icon="📘" theme="info"> Remember that despite the permissions selected in the OAuth client, agents connecting to the MCP server will be further limited by the subset of data and permissions that the user who connects the agent has access to. </Callout> <Callout icon="📘" theme="info"> If you change the resource permissions after the initial setup, you must disconnect and re-authorize your connection with your AI assistant ("Connect your AI Assistant" steps) before the new permissions take effect. </Callout> 6. Save the app. <br /> ### 2. If those scopes exceed what you enabled on the Front developer app, the authorization flow may return an error. If you encounter this error, configure your client to only request the scopes your app is set up for. In Claude, for example, this is set in the client's JSON config. See Claude's [docs on restricting OAuth scopes](https://code.claude.com/docs/en/mcp#restrict-oauth-scopes) for the exact syntax. Other clients have similar settings; check their documentation if you hit an authorization error. </Callout> When the client first connects, each user will be redirected to Front to log in and consent to the requested scopes. The resulting token is bound to that specific Front user and they can only act on data their Front role allows. <Callout icon="📘" theme="info"> **A note on enterprise deployment:** If your AI assistant is centrally managed (e.g. Claude Enterprise, ChatGPT Enterprise), your IT team may need to allow the connection or distribute the app credentials. Each end user still completes the OAuth consent flow individually. This is how Front guarantees that every tool call has a real, attributable user behind it. </Callout> ### Getting access to new tools When Front adds a tool that needs a permission your connection doesn't have yet, the tool appears in your AI assistant, but calling it returns a `missing required scopes` error. That's because a connection keeps the permissions that were approved when it was first authorized; it doesn't pick up new ones on its own. What you need to do depends on how you connected. <Callout icon="📘" theme="info"> **Connected from the Claude or ChatGPT directory** Front keeps the directory apps up to date, so there's nothing to change in Front. Each user disconnects Front in their AI assistant, connects it again, and approves the new permission on the consent screen. </Callout> <Callout icon="📘" theme="info"> **Connected with your own developer app** 1. A Front admin opens your developer app (**Settings > Company > Developer**), opens its **Front MCP** feature, and enables the new permission under **Resource permissions**. The error message names the permission the tool needs. 2. Each user disconnects Front in their AI assistant and connects it again. Until both steps are done, the new tool keeps returning the error. Other tools keep working. </Callout> ## Rate limits The Front MCP server meters usage in tool calls per minute. Every tool costs the same, regardless of which one it is or how much data it returns. MCP server limits are independent of Core API limits. Tool calls never draw down your API rate limit, and API requests never draw down your MCP limit. ### Limits by plan <Callout icon="📘" theme="info"> ### The limits are minimums rather than absolute ceilings Capacity refills continuously instead of resetting on a fixed schedule, so unused capacity accumulates. If your agent has been idle or running below its limit, it can briefly exceed the numbers in the table before settling back. </Callout> | Plan | Tools call per minute | | ------------ | --------------------- | | Starter | 100 | | Professional | 200 | | Enterprise | 300 | **Limits are keyed on the teammate connecting to the MCP server. Connecting additional MCP clients under the same teammate authorization neither increases nor divides the limit.** Capacity refills continuously rather than resetting on a fixed schedule, so short bursts above the stated rate are expected as long as your sustained usage stays below it. ### Limits by developer apps Unpublished apps in your company share a single pool, so adding more apps divides the available capacity rather than multiplying it. An app published in our App Store gets its own pool per install. ### How to handle a limit When you hit an MCP server rate limit, the server returns the rejection as a tool result rather than an HTTP error. The message tells your AI assistant how long to wait and, where one exists, points to a cheaper alternative tool. The message also tells your assistant which limit it hit.&#x20; * If it ran out of budget, your assistant needs to wait for capacity to refill. * If it hit a safety cap, your assistant needs to slow its request rate. Every response carries your limit, remaining capacity, reset timing, and what the request cost. Wait the stated time before retrying. Earlier retries will simply be rejected again. <Callout icon="📘" theme="info"> If you need a rate limit increase, you can change your plan or purchase an add-on. For more details on plans and add-ons, visit our [Pricing](https://front.com/pricing) page. </Callout> ### AI agents AI agents have their own separate limits. Common causes: * The user revoked the app's access in Front's connected apps settings. * A company admin uninstalled the OAuth app entirely. * The access token expired and the refresh flow didn't fire. Re-authenticate to mint a new token. ### `missing required scopes` on a tool Your connection doesn't have a permission this tool needs. This usually happens after Front adds a tool. See [Getting access to new tools](#getting-access-to-new-tools). ### A tool stops working after a user's Front access changes A tool can also fail if the authenticated Front user lost access to the relevant inbox, team, or resource between authorization and the tool call. Permissions are enforced at call time against the user's current Front role. ### `429 Too Many Requests` If you're seeing rate-limit errors during normal operation, the most common cause is a polling loop that's tighter than it needs to be. Approval-by-polling loops should generally poll on the order of seconds-to-minutes, not sub-second.
