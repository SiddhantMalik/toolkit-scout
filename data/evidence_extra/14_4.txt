These apps can be private to one customer or be made available to all customers through the App Store. Whether you are building backend integrations with the Core API, creating a UI element with a plugin, adding a new channels to Front, or building with our no-code Connectors framework, you will deploy your integration as an app in Front. ![](https://files.readme.io/2bab83a-Capture.PNG "Capture.PNG") <Callout icon="📘" theme="info"> ### You must be a **_company_** admin to create or manage apps. </Callout> ## Quick links within this topic * [Create an app](#create-an-app) * [Add an app channel feature to your app](#create-an-app-channel) * [Add a plugin feature to your app](#create-a-plugin) * [Add a Connector feature to your app](#create-a-connector) * [Add a webhook feature to your app](#create-a-webhook) * [Add an application trigger feature to your app](#create-an-application-trigger) * [Obtain OAuth credentials](#obtain-oauth-credentials-for-your-app) * [Configure a server for your app](#configure-servers-for-your-app) * [Publish your app](#publish-your-app) # Create an app To create an app: 1. The following features are available: * [App channel](#create-an-app-channel)—Allows you to connect a messaging source to your app (SMS providers, social media channels, live chat widgets, etc.) so users can send and receive messages within a Front inbox. Utilizes [Channels](https://dev.frontapp.com/docs/channels-overview). * [Plugin](#create-a-plugin)—Embeds a custom web app into Front that allows users to obtain additional context on a conversation or perform actions that leverage or propagate to a third-party system. Utilizes the [Plugin SDK](https://dev.frontapp.com/docs/plugin-overview). * [Connector](#create-a-connector)—Activates [Connectors](https://help.front.com/en/categories/330-connectors) that link Front to external systems through a no-code integration framework. * [Webhook](#create-a-webhook)—Adds an event listener that notifies an external server of different Front events. * [Trigger](#create-an-application-trigger)—Listens for events in external systems in order to initiate workflows in Front. * [OAuth](#obtain-oauth-credentials-for-your-app)—Allows users to authorize external system access to Front instances for purposes of syncing data or performing programmatic actions. Click **Create**. ## Create a Connector Connectors let your app bring data and actions from an external system into Front. There are three types, depending on how Front connects to your tool. * **Application objects** transform URLs or strings found in comments or messages into structured Orders, Shipments, Itineraries, Tasks, and similar records that are easy to access right from a conversation. Learn how to create an application object in our [Help Center article](https://help.front.com/en/articles/2002). * **Application requests** make API calls to external systems, either to fetch data or take an action such as creating an order or updating a record. Application requests can also be called by Front's AI on its own. Learn how to create an application request in our [Help Center article](https://help.front.com/en/articles/1237568). * **MCP Connectors** link Front to an external tool's MCP server, exposing its set of actions so Front's AI can use them directly without you building each call. To create an MCP Connector: 1. Click an app on the Developers page to view its details. 2. Click the **Features** tab. 3. Click **Add feature**. 4. Click **MCP server**. 5. Enter the URL where the MCP server is hosted. 6. Review the authentication settings and sign in when prompted. Front can register an OAuth client automatically when the server supports it. 7. Review the server's tools and permissions. Block any tools you don't want Front AI to use. 8. Click **Create.** Learn more about [Connectors](https://dev.frontapp.com/docs/overview-2) on our Developer Portal. ## Create a webhook Application webhooks allow you to be automatically notified when something happens in Front without having to constantly poll the API. Front recommends that you implement OAuth for apps that need to fetch or update data from Front on behalf of a Front user. If you are publishing your app to the App Store, OAuth becomes a requirement for receiving and utilizing data through the Core API or webhooks for any customers that install your app. <Callout icon="📘" theme="info"> End users authorizing OAuth apps must be admins. This applies to both private and public OAuth apps.<br /><br />The only exception is when authorizing OAuth for our [MCP server.](https://dev.frontapp.com/docs/mcp-server) That connection uses user-scoped tokens, so any Front teammate can authorize it. &#x20; </Callout> You can use OAuth to authorize requests to the [Core API](https://dev.frontapp.com/docs/core-api-overview) or to authorize users for your [app channel](https://dev.frontapp.com/docs/channels-overview) or to receive [webhook](https://dev.frontapp.com/docs/webhooks-1) events from other customer instances. By implementing an OAuth flow, an authorized app receives an access token to make requests to Front for authorized data. Complete the following steps to view your OAuth client ID and secret and to configure redirect URLs: 1. Click an app on the Developers page to view its details. 2. Click the **Features** tab. 3. Click **Add feature**. 4. Click **OAuth** and then **Enable OAuth**. 5. Note the **Client ID** and **Client secret**. 6. Click **Add Redirect URL** to authorize a URL for the server to redirect to after a successful authorization. You can add multiple redirect URLs, but Front recommends you delete your development URLs once your app is live. 7. Specify the **features, namespaces, and permissions** that you want users to authorize for your token. ### Features The following features specify what functionality your token can be used for: * **Access resources** allows you to manage Core API resources such as conversations, contacts, inboxes, etc. * **Auto-provisioning** allows you to manage provisioning resources using our SCIM implementation, which you have to contact our team to learn more about (not generally available to the public). * **Application triggers** allows you to [process events and payloads](https://dev.frontapp.com/docs/application-triggers) from external services (not currently available for OAuth tokens). * **MCP server** allows you to connect Front data exposed via MCP server to clients like Claude, ChatGPT, and others (not available for API tokens). ### Namespaces The following namespaces specify the scope of tokens: * **Global resources** are resources available across the company. These are resources created at the company level such as company-level rules, company-level tags, or resources that only exist at the company level, such as teams or accounts. Global resources exclude resources that belong to to specific workspaces, which are separately configured as shared resources. * **Shared resources** are resources that belong to specific workspaces, such as shared inboxes or workspace tags. You can select **All shared workspaces** to manage resources across all your workspaces. * **Private resources** are resources that belong to individual teammates, such as personal inboxes or signatures. The teammate will have to enable API access in their settings for the token to manage their resources. ### Permissions If you selected to access resources, you can granularly specify what access the token has to each resources (read, write, delete, and send). <Callout icon="👍" theme="okay"> Tips for using permissions * Refer to the API endpoint topics in the [Core API reference documentation](https://dev.frontapp.com/reference/introduction) to learn which permissions are required for each endpoint. * Front recommends limiting the permissions for each token to prevent misuse or security issues. * The following permissions exist: * **Read** for retrieving resource information. * **Write** for creating and updating resources. * **Delete** for removing API resources. * **Send** for creating and sending messages in Front, such as you would do with endpoints like [Create message](https://dev.frontapp.com/reference/create-message), which start new conversations or reply to active conversations. This is different from endpoints that [import historical messages](https://dev.frontapp.com/reference/import-inbox-message), which only require the Write permission. </Callout> To learn more about how authentication works on the Front Platform, refer to the following links: * [Core API Authentication](https://dev.frontapp.com/docs/authentication) * [Channel Authorization](https://dev.frontapp.com/docs/creating-a-partner-channel#channel-authorization) ## Configure servers for your app Servers allow you to define how users authorize or make requests through your app. By configuring a server, you can have Front handle user authentication on your behalf.
