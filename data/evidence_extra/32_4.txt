 Connect an MCP client to Meta # Connect an MCP client to Meta
Use this guide to connect a supported AI client to a remote Meta MCP server and authorize access with OAuth. When you finish, your client can discover and execute the server's available tools.
## Before you begin
To connect a client, you need:
- A current version of a supported AI client.
- A Meta account with access to the assets that the server manages. Assets are the businesses, apps, and accounts that you select when you grant consent.
- A Meta app, only if the server-specific page requires a client ID.
Open the documentation for the MCP server that you want to use, starting from the [list of available Meta MCP servers](https://developers.facebook.com/documentation/mcp#available-mcp-servers). A client is supported on a given server only if that server's page lists it.
The server-specific page is the source of truth for:
- The server name and URL.
- Which clients that server supports.
- Whether your client needs a Meta App ID.
- Required permissions.
- Any redirect URI or Meta app configuration.
- A read-only tool to use when verifying the connection.
## Determine whether you need a client ID
Check the server-specific page before configuring your client. If it requires a client ID, use a developer-provided client ID. Otherwise, use automatic registration.
### Automatic registration
Automatic registration uses OAuth dynamic client registration. The server recognizes the client during OAuth setup and returns its registered OAuth app identity. You don't need to create a Meta app or provide an App ID.
Each server recognizes a specific set of clients. If a server doesn't recognize yours, it declines automatic registration, and you need a developer-provided client ID instead.
### Developer-provided client ID
Use a developer-provided client ID when the server-specific page requires one, or when the server doesn't recognize your client. Follow that page's instructions to create or configure a Meta app, including its redirect URI. Then use the app's **App ID** as the OAuth client ID.
For example, connecting to the Meta Ads MCP server with your own Meta app uses this path. Its [Get started](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started) page describes the app setup and redirect URL.
The Meta MCP servers listed on this site use OAuth public clients with Proof Key for Code Exchange. Don't enter or share an App Secret.
## Connect your client
To connect a Meta MCP server, choose `<SERVER_ALIAS>` as a short local identifier without spaces, such as `meta_server`. Replace `<SERVER_URL>` with the URL from the server-specific page. Replace `<META_APP_ID>` with your Meta app's App ID only when that page requires a client ID.
Graphical clients ask for a server name rather than a local alias. In those clients, use the server name from the server-specific page, which can contain spaces.
For example, the Meta Social Technologies MCP server publishes the URL `https://mcp.facebook.com/devtools`, so a complete Codex CLI command with the alias `meta_devtools` is:
```bash
codex mcp add meta_devtools --url https://mcp.facebook.com/devtools
```
### Claude Code and Desktop
In Claude Code, add the server:
```bash
claude mcp add --transport http <SERVER_ALIAS> <SERVER_URL>
```
Claude Code adds the server to the local scope, which covers the current project only. To use the server in every project, add `--scope user`.
If the server-specific page requires a client ID, include your Meta App ID. Claude Code picks a random callback port unless you set one, so a redirect URI you registered in advance can't match. Set the port with `--callback-port`:
```bash
claude mcp add --transport http \
 --client-id <META_APP_ID> \
 --callback-port <PORT> \
 <SERVER_ALIAS> <SERVER_URL>
```
Claude Code then uses the callback URI `http://localhost:<PORT>/callback`. Don't pass `--client-secret`.
Run `/mcp` in a Claude Code session, select the server, and authenticate. To start the same sign-in from your shell, run `claude mcp login <SERVER_ALIAS>`, adding `--no-browser` to print the authorization URL instead of opening a browser.
To check the connection from your shell, run `claude mcp list` or `claude mcp get <SERVER_ALIAS>`. A connected server shows `Connected`, and one that still needs sign-in shows `Needs authentication`.
In Claude Desktop or Claude on the web, open **Settings** > **Connectors** > **Add custom connector**, then enter the server name and URL. If the connection requires a client ID or redirect URI configuration, follow the server-specific page.
### ChatGPT
ChatGPT connects to remote MCP servers through connectors, which require Developer mode.
1. In ChatGPT, open **Settings** > **Connectors** > **Advanced settings**, then turn on **Developer mode**.
2. Go to **Settings** > **Connectors** and create a connector.
3. Enter the server name and URL from the server-specific page.
4. Select **OAuth** for authentication. If the server requires a client ID, provide your Meta App ID as the OAuth client ID.
5. Create the connector, then complete the [OAuth authorization](#complete-oauth-authorization).
During a conversation, select the server from the composer's **Developer mode** menu.
Developer mode enables both read and write tools. Review each tool call before you approve it.
### Codex CLI
For automatic registration, add the server:
```bash
codex mcp add <SERVER_ALIAS> --url <SERVER_URL>
```
If the server-specific page requires a client ID, add the server with your Meta App ID:
```bash
codex mcp add <SERVER_ALIAS> \
 --url <SERVER_URL> \
 --oauth-client-id <META_APP_ID>
```
Codex starts sign-in automatically when it can discover the server's authorization configuration. If Codex adds the server without starting OAuth, run `codex mcp login <SERVER_ALIAS>`. Complete the [OAuth authorization](#complete-oauth-authorization) before using the server.
### Codex app
For automatic registration:
1. Open **Settings**, then select **MCP servers**.
2. Select **Add server**.
3. Choose **Streamable HTTP**.
4. Enter the server name and URL from the server-specific page.
5. Save the server, then select **Restart**.
6. In the server list, select **Authenticate** next to the server.
To confirm the connection, type `/mcp` in the composer to view connected servers.
If the server requires a client ID, use the Codex CLI instructions to add it. The desktop app, Codex CLI, and the IDE extension share the same `~/.codex/config.toml` configuration, so you can switch between them without repeating setup.
### Cursor
Cursor reads MCP servers from `~/.cursor/mcp.json` for all projects, or `.cursor/mcp.json` for one project. Add the server:
```json
{
 "mcpServers": {
 "<SERVER_ALIAS>": {
 "type": "streamable-http",
 "url": "<SERVER_URL>"
 }
 }
}
```
You can install and manage MCP servers from **Customize** in the sidebar. The Cursor CLI reads the same `mcp.json` file and prompts you to authenticate the first time it uses the server.
If the server-specific page requires a client ID, add an `auth` object to the entry:
```json
{
 "mcpServers": {
 "<SERVER_ALIAS>": {
 "type": "streamable-http",
 "url": "<SERVER_URL>",
 "auth": {
 "CLIENT_ID": "<META_APP_ID>"
 }
 }
 }
}
```
Meta MCP servers are public clients, so omit `CLIENT_SECRET`. Cursor uses fixed OAuth redirect URLs, so register both of these on your Meta app:
```text
https://www.cursor.com/agents/mcp/oauth/callback
http://localhost:8787/callback
```
The first covers Cursor on the web, the second covers the desktop app. Register both if you authenticate from both.
## Complete OAuth authorization
After adding the Meta MCP server to your client:
1. If authentication doesn't start automatically, start it from your client.
2. Sign in with the Meta account that has access to the required assets.
3. Review the requested permissions and, when prompted, select the assets that the agent can access.
4. Approve the request.
5. Return to the client and wait for it to report that the server is connected.
If a command-line client prints an authorization URL instead of opening a browser, copy the URL into your browser and finish the same flow.
Whether you sign in again after restarting depends on your client. Clients that store OAuth credentials persistently reuse them across restarts. Clients that hold them in memory prompt you to sign in again.
## Verify the connection
To verify the Meta MCP connection:
1. Restart your client so that it requests the server's tool list. Sign in again if your client prompts you.
2. Confirm that the client shows the server as connected.
3. Ask the agent to list the tools available from that server.
4. Run the read-only operation recommended on the server-specific page.
The connection works when the tool list is not empty and the read-only operation returns data instead of an authentication or permission error.
For Codex CLI, you can also inspect the saved server configuration, using the `<SERVER_ALIAS>` that you chose in [Connect your client](#connect-your-client):
```bash
codex mcp get <SERVER_ALIAS>
```
Seeing the configuration confirms that you added the server, but you must still list or call a tool to verify authentication.
## Troubleshoot authentication
Use the following resolutions for Meta MCP authentication failures:
| Problem | Resolution |
|---|---|
| "Dynamic registration is not available for this client." | The server doesn't recognize your client. Check whether the server page documents a developer-provided client ID. If it does, reconnect using that path. Otherwise, use a client that the server page lists as supported. |
| "It looks like this app isn't available." | Your account doesn't have approved access to that server yet. Check the server page for its availability and access requirements. |
| "Facebook login is currently unavailable for this app" | Your MCP client isn't supported on that server yet. Check the server page's supported-client list. |
| "The provided `redirect_uris` are not registered for this client." | The callback URI that your client sent isn't registered on the Meta app behind that client. On the automatic registration path, you can't change that app. Use a client that the server page lists as supported, or ask the server's support channel. |
| The redirect URI is invalid or doesn't match, when using a developer-provided client ID | Register the exact callback URI your client uses on your Meta app. Each client uses a different one, and several let you fix the port rather than choosing a random one — see your client's tab above. |
| The browser doesn't open | Open the authorization URL printed by the client. |
| Sign-in succeeds, but no tools appear | Reconnect the server from your client. If tools still don't appear, restart the client so that it requests the tool list again, and sign in again if prompted. |
| "The Mcp-Session-Id is unknown or has expired." | The session expired, which is separate from your sign-in. Your client starts a new session automatically on its next request. Reconnect the server if it doesn't. |
| A tool reports insufficient permissions | Sign in again and grant the required scope, or choose an asset that your account can access. If granting the scope again doesn't help, the tool might need an app capability or asset role that a scope grant can't supply. Check the server page's prerequisites. |
## Authenticate again or revoke access
To authenticate with the Meta MCP server again, use your client's authentication controls. In Codex CLI, clear the current authorization and start a new sign-in, using the `<SERVER_ALIAS>` that you chose in [Connect your client](#connect-your-client):
```bash
codex mcp logout <SERVER_ALIAS>
codex mcp login <SERVER_ALIAS>
```
In Claude Code, clear the stored credentials and start a new sign-in:
```bash
claude mcp logout <SERVER_ALIAS>
claude mcp login <SERVER_ALIAS>
```
You can also select **Clear authentication** or **Re-authenticate** on the server in the `/mcp` panel.
To change what an agent can reach without disconnecting it, adjust the permissions you granted in your Business Integrations settings.
To revoke the integration at Meta, go to **Settings** > **Your Activity** > **Business Integrations** on Facebook, select the integration, and remove its access. The client can't call authorized tools again until you complete OAuth authorization.
## Get help
If you still can't connect, recheck the server-specific page's prerequisites and supported clients. To report a problem, use the feedback link on the server-specific page, where one is listed.
