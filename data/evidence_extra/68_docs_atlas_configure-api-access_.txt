Docs Menu Ask MongoDB AI Get Started with the Atlas Administration API Copy page Interface Atlas UI Atlas Administration API Atlas CLI Authentication Method Important Each Atlas Administration API has its own resources and requires initial setup. You can access the Atlas Administration API servers through the public Internet only. The Atlas Administration API is not available over connections that use network peering or private endpoints. To learn more, see Atlas Programmatic Access. The Atlas Administration API follows the principles of the REST architectural style to expose a number of internal resources which enable programmatic access to administrative features in Atlas. To learn more about the Atlas Administration API, see Atlas Administration API Reference. The Atlas Administration API doesn&#x27;t provide access to the data stored in your clusters. To read or write data in a database, you must authenticate to your cluster using the credentials for a database user with the appropriate read or write roles . You can use the Atlas Administration API to create and manage database users. To use the Atlas Administration API to manage your Atlas clusters, you must authenticate your API requests with one of the following authentication methods: Service account access tokens ( OAuth 2.0) API keys ( HTTP Digest Authentication) To learn about these methods, see Atlas Administration API Authentication Methods. The following sections describe how to use service accounts and API keys to configure programmatic access to your Atlas organizations and projects. Note Before You Begin Before configuring programmatic access, confirm the following: You have an Atlas account. To create one, see Create an Atlas Account. An Atlas organization exists. To create one, see Create an Organization. Required Access To create a service account or API keys for an organization, you must have Organization Owner access to that organization. To grant a service account access to a project, you must have Organization Owner access to the organization that owns the project. To grant API keys access to a project, you must have Project Owner access for that project. Optional: Require an IP Access List When you create an organization using the Atlas UI, Atlas requires an IP access list for the Atlas Administration API. This limits API requests to only those from the location-based IP or CIDR addresses that you specify in the IP access list. If you make a request to the Atlas Administration API without an IP access list entry, the server responds with a 403 status code. If you disable this feature, you can make API requests from any address on the Internet as long as the IP access list is empty. Once you add an IP access list entry, only requests originating from that IP address can make requests. Note IP access lists apply to using service account access tokens, not creating or revoking them. You can generate a token from any IP address, but you can only use it to call the API if your IP address is on the access list. Note IP access lists apply only to programmatic API keys and service accounts. They don&#x27;t apply to other types of access to the Atlas Administration API, such as the Atlas CLI or delegated access granted through Atlas App Connections. Delegated access includes third-party partner applications, MongoDB applications such as MongoDB Compass , and Model Context Protocol (MCP) clients. If your organization requires all Atlas Administration API traffic to originate from specific addresses, don&#x27;t enable delegated app access for that organization. Delegated access settings for partner applications and MCP clients are off by default in existing organizations. To set your organization to require IP access lists for every Atlas Administration API request after organization creation, follow these steps: 1 In Atlas , go to the Organization Settings page. If it&#x27;s not already displayed, select your desired organization from the Organizations menu in the navigation bar. In the sidebar, click Organization Settings . The Organization Settings page displays. 2 Toggle the Require IP Access List for the Atlas Administration API setting to On . Grant Programmatic Access to an Organization Grant Programmatic Access to a Project To learn more about these two authentication methods, see Atlas Administration API Authentication Methods. To give API keys access to a project, you must have Project Access Manager or Project Owner access for that project. Add Project Access from a Project If you haven&#x27;t already created a service account or API keys for an organization, you can create them for a project to grant that project access to the Atlas Administration API. The service account or API keys that you create for a project are automatically added to the parent organization with the permission Organization Member . Make an API Request The Atlas Administration API uses one of two authentication methods to authenticate requests: service account or API keys. You&#x27;ll need the keys or secret that you saved when configuring your preferred authentication method to complete the following procedures. All Atlas Administration API endpoints have the following base URL: https://cloud.mongodb.com/api/atlas/&lt;version&gt; Important MongoDB uses HTTPS URLs to increase security. Using HTTP URLs will return a 301 status code. Tip Atlas Administration API Specification Atlas Administration API Error Codes Alternatively, you can use any tool that supports OpenAPI v3 specification to generate code samples or mock servers. For example, you can import the Atlas Admin API Specification into Postman to generate curl commands. Warning Using an HTTP URL with Postman will return a 301 status code as expected. However, in this scenario, Postman may automatically retry the request with HTTPS, but simultaneously strip the header and body from the retry request. This will return a 401 status code instead of 301, making it difficult to determine why the request failed. To use Postman to generate curl commands: 1 In the MongoDB Atlas Administration API documentation , click Download source in the navigation bar. 2 Right-click the OpenAPI specification format you want to download and copy the link. 3 Open Postman and click File , then Import . The Import window displays. 4 In the Import window, click Link and paste the download link that you copied in step 2. 5 Click Continue , then Import . 6 For the request for which you want to generate a curl command, click &lt;/&gt; on the right and select cURL from the Code snippet dropdown.
