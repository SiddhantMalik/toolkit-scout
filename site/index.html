Toolkit Scout

I built an agent pipeline that researched 100 apps the way a toolkit team would: how auth works, whether a developer can get credentials alone, what the API covers, whether an official MCP exists, and what blocks a toolkit. Every answer carries a quote and the URL it came from. Then I measured how often it was right.

By Siddhant Malik · sidmalik.dev · Source code: github.com/SiddhantMalik/toolkit-scout

The answer in 30 seconds

  1. Getting a developer key is easy. Production is where the gates are. 77 of 100 apps hand out free or trial credentials, but 25 of those add a gate before going live (app review, partner approval, KYC or a paid plan).
  2. An official MCP server is now the norm: 83 of 100 apps. Working from memory, my first pass missed 39 of them.
  3. Easy wins are productivity and data/SEO tools. Fintech, ecommerce and support need outreach.
  4. Reading the docs beat memory on a random sample, and a human check of 10 random apps found no errors. The buildability verdict is the weak spot: treat it as a hint.

What to trust less.
  1. The buildability verdict agreed with the reference answers only 55% of the time (65% from memory). The fields and blocker codes are solid; the one-word label is not.
  2. The reference ("gold") answers and both audits were made by separate Claude agents, not people. The only human check is 10 apps, so it supports "at least about 72% of apps fully right", not 100%.
  3. The random sample is 20 apps, so every accuracy figure is roughly ±20 points.

01Patterns

Counts cover all 100 apps. The pipeline couldn't settle 5 of them (Paygent Connect, YouTube Transcript, Gladly, Otter AI, PitchBook); I settled those by hand in a browser (see Verification).

Self-serve to start, gated to ship

77 of 100 apps give free or trial dev credentials; only 15 gate the first key and 7 need a paid plan. But 25 of the 77 self-serve apps add a production gate.

OAuth2 and API keys, usually both

OAuth2 in 77 apps, an API key or bearer token in 76, Basic in 13, JWT in 5. Only 15 are key-only, so a toolkit needs an OAuth flow almost everywhere.

Official MCP servers are everywhere, but not all finished

83 of 100 (73 hosted, 10 local). About 8 are beta or early access, and some cover only part of the product.

Details

Beta or preview examples: Stripe, Podio, BigCommerce, WooCommerce. Plaid's covers Dashboard diagnostics only. Docs-only MCPs (Mailchimp, Magento, Shopify's dev MCP) are not counted. "Has an official MCP" doesn't mean "toolkit done".

The common blockers are friction, not paywalls

A separate host per customer, production approval, app review and admin-only credentials each show up as often as paid plans or more.

03The agent, and where a human stepped in

Seven stages. The memory-only baseline exists so there is something to measure the evidence-grounded agent against.

0 · Baseline memoryA first pass written from model memory alone, before any docs were opened.
1 · Retrieve scriptFetches each app's docs, its llms.txt, and one hop to auth, pricing and MCP pages. Flags pages that only render with JavaScript.
2 · Extract 10 LLM agentsParallel Claude agents, one prompt and schema. Every field needs a verbatim quote and a URL, or it stays "unknown".
3 · Verify quotes scriptChecks that every quote really appears on the saved page; a field whose quotes all fail is reset to unknown.
3b · Re-fetch via Composio Composio MCPFor sites that block scripts, asks Composio's MCP for a page fetcher and pulls the cited pages, so those quotes can be checked too.
4 · Verdict codeA fixed rubric turns the fields into easy, caveat, hard or no, so the label is reproducible.
5 · Score scriptCompares every pass with reference answers that were frozen before scoring.

04Verification: how accuracy moved

The fair test is a random sample of 20 apps (2 per category) whose reference answers were written blind, before the agent ran.

Random held-out sample, 20 apps: memory alone → evidence-grounded agent
Official MCP?16/20→ 20/20
Dev access15/20→ 19/20
Auth methods14/20→ 18/20
Verdict65%→ 55% (worse)
Then each loop: quote check→Composio re-fetch→re-quote→browser on last 5 apps→human check: 10/10

What each loop did

  • Reading the docs did most of the work. Official-MCP detection rose from 16/20 to 20/20, and from 8/24 to 22/24 on a harder set of 27 apps. Most of that is freshness: MCP launches and renames from 2025–26 that memory can't know.
  • The quote check caught paraphrases, not wrong facts. Of 575 quotes, 568 are found word for word in the docs saved for that app, 6 aren't and 1 couldn't be checked (its cited page is a 404).
  • Composio closed the gap the scripts left. 33 quotes came from sites that block scripts. Composio fetched 20 of 21 of those pages; 27 quotes matched and 5 didn't. The misses were rewordings of true facts, but the strict check still blanked two correct MCP answers (hard-set score 22/24 → 20/24). Re-copying 3 quotes word for word from the fetched pages restored 22/24. Lark's "free starter pack" quote simply isn't on the page it cites.
  • A browser settled the last 5 apps. Paygent Connect: the brief's hint "NMI-powered" leads to gopaygent.com, whose JavaScript-only docs use NMI's terms, and signup is a merchant onboarding request, so it's customer-only. YouTube Transcript is transcriptapi.com, as the agent had picked. Gladly and PitchBook were confirmed unchanged. Otter's REST API turned out to be Enterprise-only (from a third-party write-up). I'd seen the reference answers for four of these, so this loop isn't scored.
  • The verdict got worse, and I won't pretend otherwise. 65% → 55% with the rubric as first written. The audit found holes in my rubric; the fixed version scores 65%, but I fixed it after seeing the answers, so it isn't a clean gain. Every miss is off by one step (say, caveat vs hard).

The facts held up better than the evidence did. In 13 of 30 apps at least one quote only partly supports its value (Pinterest, Magento and iPayX were wrong and are fixed). Of 40 random quotes, 39 were still on the page, 26 clearly supported their field, 6 weakly, 3 partly and 5 not at all.

What the agents got wrong or couldn't settle
  • My own seed file swapped the brief's hint for Paygent Connect for a different Japanese company, which sent the agent to the wrong firm.
  • Renamed products: fanbasis is now Commas, Coda is now Superhuman Docs, NotebookLM's API is "Gemini Notebook Enterprise".
  • Provisional: Threads' MCP type (its docs came back empty), WhatsApp's admin-only flag (no quote), Shopify's store MCP (announced, not live), WooCommerce's MCP (per-site preview).
  • Pricing pages built from icons or JavaScript couldn't be read for Copper, Devin and Pylon, so "which plan unlocks the API" is unconfirmed there.
