1 · Patterns

  1. A developer key is easy to get; production is where the gates are. {{self_dev}} of {{nr}} apps give free or trial credentials, but {{prod_friction}} of those {{self_serve_n}} add a production gate (app review, partner approval, KYC, a paid plan). Only {{gated_dev}} gate the first credential and {{paid_dev}} need a paid plan.
  2. OAuth2 and API keys, usually both. OAuth2 in {{oauth2}}/{{nr}} apps, key or bearer token in {{key}}, Basic in {{basic}}, JWT in {{jwt}}. Only {{key_only}} are key-only.
  3. An official MCP is now the norm. {{mcp_official}}/{{nr}} ({{mcp_remote}} remote, {{mcp_local}} local). My memory-only pass missed it for {{mcp_flipped}} of {{n}} apps.
    Caveats
    The second audit counted roughly 8 of these as beta, early access or preview (for example Stripe, Podio, BigCommerce, WooCommerce), and some cover only part of the product (Plaid's covers Dashboard diagnostics).   4. Blockers are friction, not paywalls. Per-tenant hosts, production approval, app review and admin-only credentials outnumber paid-plan gates.

3 · The agent, and where a human was needed

0 · Baseline memoryPass 1 written from model memory before I opened any docs (git timestamps can't prove that, so treat it as stated, not proven).
1 · Retrieve scriptfetch_evidence.py: docs, llms.txt, one hop to auth/pricing/MCP pages, JS-shell detection. mcp_probe.py: MCP Registry leads.
2 · Extract LLM agents10 parallel extractor agents, one prompt and schema. Every field needs a verbatim quote and URL, otherwise unknown.
3 · Verify scriptcheck_quotes.py looks for each quote in the page text saved for that app; gate.py resets fields whose quotes all fail.
4 · Verdict codeverdict.py derives the label from the fields, so it is reproducible.
5 · Score scriptscore.py against gold sets frozen in git before scoring.
  • What ran where. Stage 2 ran as Claude subagents (40 apps Sonnet, 60 Opus). Seven of ten first-launch runs died on API overload (HTTP 529) and were re-run, six on Opus; the log is data/run_log.json, written by me because the tooling kept no model tags. Composio was tried only briefly. Late in the session I got a key and called Composio's MCP fetch tool for 8 of the unreadable apps: 6 calls failed (shared free quota, one 404) and the one result I read (Airtable) said "not found", so no data changed (data/composio_attempt.json). The key also got a 401 from the Python SDK's REST endpoint, and no repo script calls Composio. Stages 1, 3, 4 and 5 are plain Python, and the stage-2 prompt (agent/prompts/extract.md) is model-agnostic.
  • Where the shell could not read. {{web_only_apps}} apps have at least one quote that came through a web-fetch tool rather than a saved page ({{q_web}} quotes), so it could not be machine-checked. Bot-blocked or JavaScript-only sites included Salesforce, Otter, PitchBook, Binance, Lark, Airtable, Gumroad, Consensus and the Amazon and Google docs.
  • Human involvement: none so far. {{queue_n}} apps carry an open question. The 7 that most need a person: Paygent Connect and YouTube Transcript (entity ambiguous); fanbasis, Coda and NotebookLM (renamed); Otter and PitchBook (docs unreadable to the agent). I corrected four rows myself after the second audit (Pinterest MCP, Magento auth, iPayX access, Ramp auth); they are logged in data/pass2/corrections.json, and none is in a gold set.

4 · Verification, honestly

Read first. Gold B (20 apps, seeded random, 2 per category, labelled blind before any pass-2 output existed) is the fair estimate, but at n=20 the 95% intervals are about ±20 points. Gold A (27 apps picked by a reviewer to be suspicious) exaggerates pass-1 error and is not blind: I had read its answers before launching the extractors, and extractors were only told not to open gold files. What moved accuracy, and what didn't

  • Evidence-grounded extraction did the work. Official-MCP detection went from {{b_mcp_p1}} to {{b_mcp_p2}} on the random sample and from {{a_mcp_p1}} to {{a_mcp_p2}} on the hard cases. Most of that is freshness (2025–26 vendor MCP launches, renames), which a memory-only baseline cannot know. That baseline is deliberately weak.
  • The quote gate barely mattered for accuracy. Of {{q_total}} quotes, {{q_verified}} were found in the page text saved for that app (it does not check that the text came from the cited URL), {{q_web}} could not be checked and {{q_failed}} failed. It reset one field (Cloudflare access) and changed no gold-scored result. It also had a bug of its own: it dropped non-Latin characters until a Japanese quote failed.
  • Verdict is worse than memory under the rubric as first written (v1). Gold B {{b_ver_p1}}% to {{b_ver_v1}}%, gold A {{a_ver_p1}}% to {{a_ver_v1}}%; every disagreement is within one step. The second audit found holes in my rubric (an official MCP excused gated developer access, a paid plan needed only for production never counted as friction, unknown fields defaulted to "easy"). I fixed them after seeing gold (v3, used for the per-app labels above). v3 scores {{b_ver_v3}}% on gold B (the gain is two apps, Amazon SP-API and PitchBook) and {{a_ver_v3}}% on gold A, so it is a post-hoc variant, not a clean improvement.
  • Auth fell on gold A by exact match ({{a_auth_p1}}% to {{a_auth_p2}}%). Extractors list every supported method while gold lists the reviewer's primary one, so adding OAuth to an API-key app fails exact match. Jaccard (shown beside it) is the softer metric. Neither is clean because gold A's auth labels are incomplete.
  • Pass 1 and pass 2 differ on {{drift_mcp}} MCP calls, {{drift_access}} access classes, {{drift_auth}} auth sets and {{drift_verdict}} verdicts across all {{n}} apps. Only the gold-sampled apps have ground truth to say which side was right.

Other things the agents got wrong or could not settle
  • Entities: "Paygent Connect" matches no single product; "YouTube Transcript" resolved to a third-party service (TranscriptAPI), not Google's captions API; fanbasis is now Commas; Coda is now Superhuman Docs; NotebookLM's API is the enterprise "Gemini Notebook Enterprise". All are flagged, not guessed.
  • Provisional labels: Threads' MCP type is inferred from a docs index whose pages came back empty; WhatsApp's "admin-only credential" has no quote; Shopify's store-management MCP is announced but not live (recorded docs-only); WooCommerce's MCP is a per-site developer preview.
  • Pricing tables rendered as icons or JavaScript could not be read for Copper, Devin and Pylon, so "which plan unlocks the API" is unconfirmed there.

6 · Run it

One command rebuilds every number and this page from the committed research data (about 5 seconds, offline).

pip install -r requirements.txt
python agent/run_all.py              # gate -> score -> analyze -> build the page
python -m pytest -q tests            # rubric, scorer and quote-checker tests
python agent/run_all.py --research   # also re-fetch evidence (needs network)

Stage 2 (LLM extraction) is run by giving agent/prompts/extract.md to any agent with web and shell tools; outputs go to data/pass2/raw_*.jsonl.
