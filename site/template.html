4 · Verification, honestly

Read first. Gold B (20 apps, seeded random, 2 per category, labelled blind before any pass-2 output existed) is the fair estimate, but at n=20 the 95% intervals are about ±20 points. Gold A (27 apps picked by a reviewer to be suspicious) exaggerates pass-1 error and is not blind: I had read its answers before launching the extractors, and extractors were only told not to open gold files. Treat gold A's pass-2 numbers as contaminated.

What moved accuracy, and what didn't

  • Evidence-grounded extraction did the work. Official-MCP detection went from {{b_mcp_p1}} to {{b_mcp_p2}} on the random sample and from {{a_mcp_p1}} to {{a_mcp_p2}} on the hard cases. Most of that is freshness (2025–26 vendor MCP launches, renames), which a memory-only baseline cannot know. That baseline is deliberately weak.
  • The quote gate barely moved accuracy. Of {{q_total}} final quotes, {{q_verified}} are found verbatim in saved page text, {{q_failed}} fail and {{q_web}} is unchecked. Quotes from pages the scripts saved are matched against everything saved for that app, not the exact cited URL; web-tool quotes are matched against the Composio copy of the cited page. The gate's final resets (Cloudflare access, and Otter access, which was already "unknown") change no gold-scored field.
  • The Composio loop closed the unchecked gap, and it showed the gate's cost. {{cx_web}} quotes had come through a web tool from sites my shell couldn't read. Composio fetched {{cx_pages_ok}} of their {{cx_pages}} cited pages (one cited PitchBook URL is a 404). Checked against the page each quote cites, {{cx_verified}} matched, {{cx_failed}} did not and {{cx_unchecked}} stayed unchecked. Most misses were paraphrases of true facts ("Spot Account" for "Spot Wallet", an added "Remote"), and the strict gate turned two correct MCP answers on gold A (Salesforce, Otter) into abstentions: {{cx_a_mcp_final}} became {{cx_a_mcp_strict}}. A re-quote step replaced {{cx_requoted}} quotes ({{cx_requote_names}}) with text taken from the fetched page, without changing any value, and re-checked them: MCP went back to {{cx_a_mcp_final}}. {{cx_failed_after}} quotes still fail. One, Lark's "free starter pack" line, is simply not on the pricing page it cites; the other is Otter's access quote, whose value is already "unknown". I did the re-quoting as the orchestrator, so it is logged in data/pass2/requote.jsonl, and the row "Pass 2b strict" in the tables shows the score before it.
  • Verdict is worse than memory under the rubric as first written (v1). Gold B {{b_ver_p1}}% to {{b_ver_v1}}%, gold A {{a_ver_p1}}% to {{a_ver_v1}}%; every disagreement is within one step. The second audit found holes in my rubric (an official MCP excused gated developer access, a paid plan needed only for production never counted as friction, unknown fields defaulted to "easy"). I fixed them after seeing gold (v3, used for the per-app labels above). v3 scores {{b_ver_v3}}% on gold B (the gain is two apps, Amazon SP-API and PitchBook) and {{a_ver_v3}}% on gold A, so it is a post-hoc variant, not a clean improvement.
  • Auth fell on gold A by exact match ({{a_auth_p1}}% to {{a_auth_p2}}%). Extractors list every supported method while gold lists the reviewer's primary one, so adding OAuth to an API-key app fails exact match. Jaccard (shown beside it) is the softer metric. Neither is clean because gold A's auth labels are incomplete.
  • Pass 1 and pass 2 differ on {{drift_mcp}} MCP calls, {{drift_access}} access classes, {{drift_auth}} auth sets and {{drift_verdict}} verdicts across all {{n}} apps. Only the gold-sampled apps have ground truth to say which side was right.

With n=30 each rate has a 95% interval about 15–20 points wide. The weak spot is evidence quality, not the facts: in {{audit_ev_bad}} of {{audit_n}} apps at least one cited quote only partly supports its value or contradicts it (Pinterest, Magento and iPayX were outright wrong and are corrected). In the 40-entry check, {{e40_present}} of {{e40_n}} quotes were still on the cited page, but only {{e40_clean}} clearly supported their field; {{e40_weak}} supported it weakly or trivially, {{e40_part}} partly and {{e40_no}} not at all. The auditor is the same model family as the extractors, so "agrees" is not human-grade truth. See audit.md.

Other things the agents got wrong or could not settle
  • Entities: "Paygent Connect" matches no single product; "YouTube Transcript" resolved to a third-party service (TranscriptAPI), not Google's captions API; fanbasis is now Commas; Coda is now Superhuman Docs; NotebookLM's API is the enterprise "Gemini Notebook Enterprise". All are flagged, not guessed.
  • Provisional labels: Threads' MCP type is inferred from a docs index whose pages came back empty; WhatsApp's "admin-only credential" has no quote; Shopify's store-management MCP is announced but not live (recorded docs-only); WooCommerce's MCP is a per-site developer preview.
  • Pricing tables rendered as icons or JavaScript could not be read for Copper, Devin and Pylon, so "which plan unlocks the API" is unconfirmed there.

6 · Run it

One command rebuilds every number and this page from the committed research data (about 5 seconds, offline).

pip install -r requirements.txt
python agent/run_all.py              # gate -> score -> analyze -> build the page
python -m pytest -q tests            # rubric, scorer and quote-checker tests
python agent/run_all.py --research   # also re-fetch evidence (needs network)
export COMPOSIO_CONSUMER_KEY=ck_...  # optional: with --research, re-check web-only quotes via Composio MCP

Stage 2 (LLM extraction) is run by giving agent/prompts/extract.md to any agent with web and shell tools; outputs go to data/pass2/raw_*.jsonl.
